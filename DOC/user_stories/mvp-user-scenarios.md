# MVP 使用者情境草案

先記錄主要使用流程，詳細操作與例外情境見 [MVP 詳細使用情境](mvp-user-scenarios-detail.md)，名詞定義見 [GLOSSARY.md](../../GLOSSARY.md)。

第一個 MVP 的預期：一定要登入；不提供好友功能，也不能查看其他使用者的足跡；使用者只查看自己的足跡與地圖。選店時可搜尋所有人建立的店家基本資料，但不顯示他人的足跡。

## MVP 範圍檢視

- 情境 1、2 為核心：留下自己的足跡，並能在自己的地圖找回店家。
- 情境 3 為回訪：到訪記錄不設限，來訪天數以不同日期計算。
- 情境 4、5 為個人足跡的維護：沒有修改功能，更正只能刪除重寫；刪除足跡不刪除共用店家。
- 系統方不定期核對店名與地址、更新店家資料並標示「已核對」，屬管理作業，與一般使用者流程分開；專用查核介面是否列入第一版仍待確認。
- 「已核對」僅代表店家身分與大概位置已核對，不代表評價、實際到訪或補充資訊已核對。
- 移出 MVP：離店後補登（到訪日期固定為記錄當下）、修改紀錄、照片、訪客模式、第三方登入。好友、他人足跡、公開探索與美食家功能不納入。

## 1. 記錄好吃的店

```mermaid
flowchart TD
    A[找到一間店，覺得好吃] --> B[打開 App，進入自己的地圖]
    B --> C[搜尋並選擇店家，找不到則填店名、點大概位置、可貼 Google 連結新增]
    C --> D[選評價，可填筆記與補充資訊]
    D --> F[回到地圖並標出店家]
    F --> H([結束])
```

## 2. 找回之前吃過的店

```mermaid
flowchart TD
    A[想找之前吃過的店] --> B[打開 App]
    B --> C[查看地圖]
    C --> D[點擊地圖上的篝火]
    D --> E[預覽卡：店名、價位、在 Google 地圖開啟]
    E --> G{要做什麼？}
    G -- 導航 --> H[開啟 Google 地圖]
    G -- 看詳細 --> I[開啟店家頁]
    H --> F([結束])
    I --> F
```

## 3. 再次到訪記錄過的店

```mermaid
flowchart TD
    A[再次到訪記錄過的店] --> B[打開 App]
    B --> C[從地圖、我的足跡或搜尋（標已記錄）開啟店家頁]
    C --> D[按「新增到訪」，選評價，可填筆記與補充資訊]
    D --> E[回到店家頁，提示已記下；不同日期才增加來訪天數]
    E --> F([結束])
```

## 4. 刪除到訪

```mermaid
flowchart TD
    A[到訪填錯或不想保留] --> B[打開店家資料]
    B --> C[選擇一筆到訪並刪除]
    C --> D[確認刪除；過去的到訪無法補回]
    D --> E{還有其他到訪？}
    E -- 有 --> F[依剩餘到訪更新來訪天數與店家頁]
    E -- 無 --> G[足跡一併刪除，回到地圖]
    F --> H([結束])
    G --> H
```

## 5. 成為回憶、復活與永久刪除

```mermaid
flowchart TD
    A[對店家徹底失望] --> B[在店家頁按「成為回憶」並確認]
    B --> C[足跡從地圖消失，移到回憶清單]
    C --> D{之後在唯讀的回憶頁想怎麼處理？}
    D -- 復活 --> E[足跡回到地圖並置中]
    D -- 永久刪除 --> F[確認後刪除足跡與所有到訪，回到回憶清單]
    E --> G([結束])
    F --> G
```
