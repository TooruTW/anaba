# MVP 驗收條件

依 [MVP 詳細使用情境](mvp-user-scenarios-detail.md) 逐條判定，每條只有通過或不通過。第 8 階段逐項勾選；標 `[自動]` 的由測試覆蓋（Vitest 或 Playwright 主流程，見 [stack.md](../tech/stack.md)），其餘手動在手機上驗。

## 00｜註冊與登入

- [ ] 未登入時開任何網址都導向登入頁。
- [ ] 邀請碼錯誤時無法註冊，並提示邀請碼錯誤。
- [ ] 密碼少於 8 字元，或兩次密碼不一致時無法註冊。
- [ ] 註冊成功直接進入自己的地圖，系統不寄任何信。
- [ ] 關閉瀏覽器再開仍保持登入；按登出後回到登入頁。
- [ ] 登入頁顯示「忘記密碼請來信 〈聯絡信箱〉」。
- [ ] 帳號不存在與密碼錯誤顯示相同訊息「email 或密碼錯誤」。
- [ ] `[自動]` 同一 email 連續失敗 10 次後，即使密碼正確也無法登入；15 分鐘後恢復。
- [ ] `[自動]` 不存在的 email 失敗 10 次後，顯示與存在帳號相同的「嘗試次數過多，請 15 分鐘後再試」。
- [ ] `[自動]` Session 超過一個月未使用即失效；期間有使用則往後延。
- [ ] `[自動]` 資料庫中沒有明文密碼或明文 session token。
- [ ] `[自動]` 非 GET 請求的 `Origin` 不是自己網域時回 403。
- [ ] 修改密碼需輸入正確的舊密碼；成功後其他裝置的登入失效，目前裝置保持登入。
- [ ] 執行重設腳本後，該帳號所有裝置登出，可用臨時密碼登入。
- [ ] 瀏覽器載入的程式碼與網路請求中沒有 Supabase 網址或金鑰；除地圖圖資（R2）外，所有資料請求都打自己的 `/api`。
- [ ] `[自動]` A 登入後以 B 的到訪 ID 或 B 的私房店呼叫讀取、新增、刪除、成為回憶、復活、永久刪除的 API，全部回 404。

## 01｜第一次記錄店家

- [ ] 搜尋店名可找到其他使用者建立的店家，結果不顯示建立者或記錄人數。
- [ ] 允許定位時可依距離排序；拒絕定位則依店名排序。定位不寫入資料庫。
- [ ] 搜尋結果最下方一律有「新增這家店」（有結果時也有）；店名與大概位置必填，Google Maps 連結選填。
- [ ] 新增時若已有名稱相近或 Google 店家代碼相同的店家，先列出詢問「是不是這幾家？」，選「都不是」才建立。
- [ ] 2 公里內已有「阿明麵館」時，新增「阿明麵店」會被列出；最多列 5 家。
- [ ] 貼非 Google 地圖網址（如 `https://example.com`）時無法儲存，提示「請貼 Google 地圖的分享連結」。
- [ ] 評價未選無法送出；筆記超過 20 字無法送出。
- [ ] 送出後店家（若新建）與到訪一起存入；到訪時間由後端記錄，前端傳來的日期會被忽略。
- [ ] `[自動]` 台灣時間 00:30（UTC 前一天 16:30）記錄的到訪，顯示與計算來訪天數時算台灣當天。
- [ ] 送出後回到地圖，該店置中並出現篝火。
- [ ] 新建的店家立即可被其他使用者搜尋到，店家頁標「未核對」。
- [ ] 貼 `maps.app.goo.gl` 短網址時，資料庫存的是展開後的完整網址；展開失敗時仍可儲存（存短網址）。
- [ ] 有連結時「在 Google 地圖開啟」開該連結；沒有時以座標開 Google 地圖搜尋。
- [ ] 儲存失敗時保留已填內容並提示「儲存失敗，請再試一次」。

## 02｜找回之前吃過的店

- [ ] 地圖只顯示自己非回憶的私房店。
- [ ] 打開地圖：允許定位時以目前位置為中心，拒絕定位時以高雄火車站為中心，縮放比例相同（約半徑 1 公里）；完全沒有私房店時提示「記下你的第一家店」。
- [ ] 點篝火出現預覽卡（店名、自己最近填的價位、在 Google 地圖開啟），點預覽卡進店家頁；從沒填過價位時不顯示價位這行。
- [ ] 店家頁補充資訊每項顯示最近一次有填的值，從未填過顯示「不清楚」。
- [ ] 「我的私房店」清單依最近一次到訪排序，可依店名搜尋，不含回憶。
- [ ] `[自動]` 來訪天數＝不同日期（台灣時間）數；同一天兩筆到訪只算 1 天。
- [ ] `[自動]` 亮度分數＝不同使用者數＋2×來訪天數 ≥ 2 的使用者數；1–2 一級、3–5 二級、6 以上三級。
- [ ] `[自動]` 回憶中的到訪仍計入亮度；刪除到訪或永久刪除後亮度依剩餘資料重算。
- [ ] 篝火依亮度顯示三種樣式。

## 03｜再次到訪

- [ ] 搜尋選店時，自己有到訪的店標「已記錄」，點擊開店家頁而非新增表單。
- [ ] 店家頁「新增到訪」的表單沒有任何預填值。
- [ ] 儲存後回到店家頁，新到訪在列表最上方，並提示「已記下這次到訪」。
- [ ] 同一天第二筆到訪後來訪天數不變；隔天新增則 +1。

## 04｜刪除到訪

- [ ] 刪除非最後一筆時顯示「刪除這筆到訪？過去的到訪刪除後無法補回。」
- [ ] 刪除最後一筆時顯示「這是此店最後一筆到訪，刪除後這家店會從你的地圖消失，無法補回。」
- [ ] 刪除最新一筆後，店家頁的最新評價、補充資訊與預覽卡價位改為剩餘到訪中最近的值。
- [ ] 刪除最後一筆後回到地圖、該店篝火消失；其他使用者仍搜尋得到該店家。
- [ ] 介面上沒有任何修改到訪的入口。

## 05｜成為回憶、復活與永久刪除

- [ ] 按「成為回憶」需確認；確認後回到地圖，該店篝火消失。
- [ ] 回憶清單依成為回憶的時間排序（新的在上），可搜尋店名，每列顯示店名與來訪天數。
- [ ] 回憶的店家頁為不同色系，沒有新增或刪除到訪的按鈕，只有「復活」與「永久刪除」。
- [ ] 搜尋選店時，回憶中的店標「在回憶中」，點擊開回憶的店家頁。
- [ ] 按「復活」不需確認，回到地圖並以該店置中，到訪數不變。
- [ ] 永久刪除需確認「永久刪除這家店的全部 N 筆到訪？無法復原。」，刪除後回到回憶清單；其他使用者仍搜尋得到該店家。
- [ ] `[自動]` 直接呼叫 API 對回憶中的店新增或刪除到訪回 409「此店在回憶中，請先復活」（不只是介面隱藏）。

## 06｜系統方核對店家

- [ ] `[自動]` 核對兩家店後：建立一筆已核對的新店家，舊的兩家標「已被取代」並指向新店家，所有到訪改記到新店家，筆數不變。
- [ ] `[自動]` 同一人在兩家都有到訪時，核對後地圖只剩一個篝火，來訪天數為兩家到訪的不同日期合計，亮度依新結果重算。
- [ ] `[自動]` 同一人一家是回憶、一家不是時，核對後新店家不是回憶；兩家都是回憶時保留一筆回憶，時間為較晚者。
- [ ] `[自動]` 核對中途失敗時，資料完全不變。
- [ ] `[自動]` 管理 API 沒帶或帶錯 token 回 401；列出未核對店家的回應不含任何使用者資料。
- [ ] 已被取代的店家搜尋不到；打開舊店家頁會導到新店家。
