# MVP 詳細使用情境

主要流程概覽見 [MVP 使用者情境草案](mvp-user-scenarios.md)。本文件逐步討論操作、輸入、結果與例外；名詞定義見 [GLOSSARY.md](../../GLOSSARY.md)。暫不設計 API。

## 討論順序建議

1. 第一次記錄店家：已定案（2026-10-23）。
2. 找回之前吃過的店：已定案（2026-10-23），亮度計分公式另議。
3. 再次到訪：沿用新增到訪流程，釐清店家頁上的入口。
4. 刪除到訪與足跡：大方向已在情境 1 討論中確認，細節待展開。
5. 成為回憶與復活：大方向已確認，細節待展開。

系統方核對店家資料屬獨立管理作業，之後另行討論。

## 01｜第一次記錄店家

狀態：已定案（2026-10-23）。

### 使用者目的

剛吃到一家喜歡的小店，希望快速留下資訊，日後能從自己的地圖找回來。

### 邊界

- 第一個 MVP 不提供好友功能，也不能查看其他使用者的足跡。
- 一定要登入才能使用；訪客模式留待下一層 MVP。登入採 email 加密碼，不做第三方登入、不寄驗證信；試用期間忘記密碼由系統方手動重設。
- 手機定位只作為地圖起始畫面與距離排序，不直接當作店家位置；不做照片。
- 到訪日期固定為儲存當下的日期（手機本地時區），不能選擇。23:50 用餐、00:10 才記錄會算成隔天，接受此誤差。

### 操作流程

| 步驟 | 使用者操作 | 系統行為 |
| --- | --- | --- |
| 1. 進入新增 | 登入後首頁即自己的地圖，點地圖上的新增按鈕 | 開啟選店畫面 |
| 2. 選店 | 以店名搜尋共用店家庫 | 搜尋範圍不限，只找共用店家庫中的店家；可依自己的距離排序。顯示所有人建立的店家基本資料（店名），不顯示建立者或記錄人數 |
| 3a. 選到既有店家 | 點選店家 | 進入填寫到訪 |
| 3b. 找不到時新增 | 搜尋無結果時點「新增這家店」，填店名、在地圖上點大概位置，可貼 Google Maps 連結 | 若庫中有名稱相近、或 Google 店家代碼相同的店家，先列出詢問「是不是這幾家？」；確認不是才建立新店家 |
| 4. 填寫到訪 | 選評價（必填），可填筆記與補充資訊 | 見下方欄位 |
| 5. 送出 | 確認送出 | 新店家、足跡（第一次記錄時）與到訪一起儲存；送出後評價、筆記、補充資訊皆不能修改 |
| 6. 回饋 | — | 回到地圖，該店家置中並亮起篝火 |

### 到訪欄位

| 欄位 | 必填 | 規則 |
| --- | --- | --- |
| 評價 | 是 | 單選：我會推薦人來／我會再來／可以再給次機會 |
| 筆記 | 否 | 20 字以內，只有本人可見 |
| 店家種類 | 否 | 可複選：餐廳、小吃、咖啡廳、甜點店、酒吧、其他 |
| 價位（每人，新台幣） | 否 | 單選：`$` 150 以下／`$$` 150–500／`$$$` 500–1000／`$$$$` 1000–2000／`$$$$$` 2000 以上；欄位旁 ⓘ 點擊顯示級距說明 |
| 寵物 | 否 | 單選：可帶、有條件可帶、不可帶 |
| 付款方式 | 否 | 可複選：現金、信用卡、行動支付、其他 |

- 補充資訊未填代表「不清楚」。店家頁每一項顯示最近一次有填寫的值，未填過顯示「不清楚」。

### 新店家與位置

- 新店家需要店名與大概位置（必填），Google Maps 連結選填但介面鼓勵貼上。不存地址與電話，這些資訊由 Google 連結查看。
- 大概位置：使用者在地圖上點選，地圖從手機目前位置開始；拒絕定位則從目前畫面開始。使用者點的座標是自有資料，不使用任何地址轉座標服務。
- 地圖只標大概位置；精確位置與導航交給 Google 地圖。有連結時「在 Google 地圖開啟」直接開該連結；沒有連結時以座標組 Google 地圖搜尋網址，不用 API。
- 店家使用 App 自己的 ID。Google 分享短網址每次都不同，不能當 ID；後端展開短網址取出 Google 店家代碼（如 `0x…:0x…`），只作為新增時的查重提示。ponytail：此代碼依賴 Google 網址格式，格式改變時查重提示會失效，但不影響店家資料與導航。
- 私房小店（如夜市攤販）可能沒有 Google 地點，所以連結不必填。
- 新店家一建立即進入共用店家庫，其他使用者可立即搜尋選取，不必等核對。
- 系統方核對：確認連結與店名對得上、修正明顯錯誤的位置、合併重複店家，完成後標示「已核對」。「未核對」只在店家頁標示，地圖標記不區分。
- 依自己距離排序時，手機定位僅用於當下排序，不保存；拒絕定位則依店名排序。

## 02｜找回之前吃過的店

狀態：已定案（2026-10-23），亮度計分公式另議。

### 地圖

- 底圖：MapLibre＋自放 Protomaps 台灣圖資，黑色陸地、只畫主要道路與行政界線，見 [custom-map-prototype.md](../tech/custom-map-prototype.md)。
- 只顯示自己的足跡；回憶不顯示。
- 打開地圖時以手機目前位置為中心，顯示約半徑 1 公里；拒絕定位則框住所有足跡；沒有足跡時顯示台灣全圖並提示「記下你的第一家店」。定位不保存。
- 篝火樣式依店家的亮度（共用店家資料，由所有使用者的到訪與回訪累積分數決定）分三級。使用者只會間接得知店家有其他人來過，不會看到是誰或內容。計分公式於第 6 階段前定案，初步構想：有人來 +1、回頭客 +2、每月到訪人數超過一定數值 +3；>0、>30、>50 分各一級。

### 預覽卡與店家頁

- 點篝火先顯示預覽卡：店名、自己最近填的價位、「在 Google 地圖開啟」；點預覽卡進完整店家頁。
- 店家頁由上到下：店名與「未核對」標示、最新一次評價與回訪次數、補充資訊（每項顯示最近一次有填的值，否則「不清楚」）、「在 Google 地圖開啟」、「新增到訪」、到訪列表（新的在上，每筆有日期、評價、筆記與刪除按鈕）、最底部不顯眼的「成為回憶」。

### 我的足跡清單

- 個人選單有「我的足跡」清單，列出所有非回憶的足跡，依最近一次到訪排序，可依店名搜尋；回憶清單另外分開。

### 例外

- 同一店家同一天可記錄多筆到訪，不設限；回訪次數以不同日期計算，同一天多筆只算一次。
- 儲存失敗：保留已填內容，提示「儲存失敗，請再試一次」。
- 填寫到一半離開：不保留草稿。

## 刪除與回憶（大方向）

- 沒有修改功能；要更正只能刪除到訪後重寫。
- 任何一天的到訪都能刪除，回訪次數依剩餘到訪的日期重新計算；到訪日期固定為記錄當下，刪除確認需說明過去的到訪刪除後無法補回。
- 刪除足跡的最後一筆到訪時，足跡一併刪除；共用店家資料保留。
- 足跡可透過不顯眼的「成為回憶」按鈕封存：不必新增到訪或評價，原有到訪全部保留，不再出現在地圖上，期間不能新增到訪。
- 個人選單有回憶清單，點擊顯示店家頁（不同色系），最下方有「復活」按鈕；復活只讓足跡回到地圖，不產生到訪。
- 永久刪除整個足跡的按鈕只放在回憶的店家頁，需再次確認，連同所有到訪一起刪除。
