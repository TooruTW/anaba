## 00｜註冊與登入

狀態：已定案（2026-10-24）。

- 沒登入時打開任何頁面都導向登入頁；沒有地圖預覽或介紹頁。
- 註冊填 email、密碼、確認密碼、邀請碼。不填暱稱或頭像（社交功能之後再說）。
- 密碼至少 8 個字元，沒有其他複雜度要求。
- 邀請碼：試用期只有一組，放在環境變數；碼不對則不能註冊。ponytail：單一共用邀請碼，外流就得換碼；正式開放時拿掉。
- 不寄驗證信，註冊完成直接登入。
- 登入後保持登入，直到使用者在個人選單按登出，或連續一個月沒有使用。
- 同一 email 連續登入失敗 10 次鎖 15 分鐘，不論帳號是否存在都計數，鎖定時一律顯示「嘗試次數過多，請 15 分鐘後再試」；錯誤訊息不透露帳號是否存在。
- 修改密碼：個人選單輸入舊密碼與新密碼（至少 8 字元），成功後其他裝置登出。
- 刪除帳號：MVP 不做按鈕，來信聯絡信箱申請，由系統方手動刪除。到訪（含筆記）與回憶全部刪除；建立過的店家保留，只清空建立者；亮度依剩餘資料重算。
- 忘記密碼：登入頁顯示「忘記密碼請來信 〈聯絡信箱〉」，由系統方用腳本產生臨時密碼回信，該帳號所有裝置登出，使用者登入後可自行修改密碼。ponytail：無法確認來信者是帳號本人，試用者皆為邀請的熟人所以接受；正式開放時改用自有網域＋寄信服務寄重設連結，與拿掉邀請碼一起做。

## 01｜第一次記錄店家

狀態：已定案（2026-10-23）。

### 使用者目的

剛吃到一家喜歡的小店，希望快速留下資訊，日後能從自己的地圖找回來。

### 邊界

- 第一個 MVP 不提供好友功能，也不能查看其他使用者的到訪。
- 一定要登入才能使用；訪客模式留待下一層 MVP。登入規則見情境 00。
- 手機定位只作為地圖起始畫面與距離排序，不直接當作店家位置；不做照片。
- 到訪時間由後端在儲存當下記錄（資料庫存 UTC），不收前端傳來的日期，不能選擇。顯示與計算來訪天數時由後端換算成台灣時間的日期。23:50 用餐、00:10 才記錄會算成隔天，接受此誤差。ponytail：假設使用者都在台灣，出國記錄也以台灣日期計。

### 操作流程

| 步驟 | 使用者操作 | 系統行為 |
| --- | --- | --- |
| 1. 進入新增 | 登入後首頁即自己的地圖，點地圖上的新增按鈕 | 開啟選店畫面 |
| 2. 選店 | 以店名搜尋共用店家庫 | 搜尋範圍不限，只找共用店家庫中的店家；可依自己的距離排序。顯示所有人建立的店家基本資料（店名），不顯示建立者或記錄人數；結果最下方一律有「新增這家店」 |
| 3a. 選到既有店家 | 點選店家 | 沒有到訪：進入填寫到訪。標「已記錄」：開店家頁（情境 03）。標「在回憶中」：開回憶的店家頁（情境 05） |
| 3b. 找不到時新增 | 點「新增這家店」，填店名、在地圖上點大概位置，可貼 Google Maps 連結 | 若庫中有名稱相近、或 Google 店家代碼相同的店家，先列出詢問「是不是這幾家？」；確認不是才建立新店家 |
| 4. 填寫到訪 | 選評價（必填），可填筆記與補充資訊 | 見下方欄位 |
| 5. 送出 | 確認送出 | 新店家（若新建）與到訪一起儲存；送出後評價、筆記、補充資訊皆不能修改 |
| 6. 回饋 | — | 回到地圖，該店家置中並亮起篝火 |

### 到訪欄位

| 欄位 | 必填 | 規則 |
| --- | --- | --- |
| 評價 | 是 | 單選：我會推薦人來／我會再來／可以再給次機會 |
| 筆記 | 否 | 20 字以內，只有本人可見 |
| 店家種類 | 否 | 可複選：餐廳、小吃、咖啡廳、甜點店、酒吧、其他 |
| 價位（每人，新台幣） | 否 | 單選：`$` 150 以下／`$$` 150–500／`$$$` 500–1000／`$$$$` 1000–2000／`$$$$$` 2000 以上；欄位旁 ⓘ 點擊顯示級距說明 |
| 寵物 | 否 | 單選：可帶、有條件可帶、不可帶 |
| 付款方式 | 否 | 可複選：現金、信用卡、行動支付、其他 |

- 補充資訊未填代表「不清楚」。店家頁每一項顯示最近一次有填寫的值，未填過顯示「不清楚」。

### 新店家與位置

- 新店家需要店名與大概位置（必填），Google Maps 連結選填但介面鼓勵貼上。不存地址與電話，這些資訊由 Google 連結查看。
- 大概位置：使用者在地圖上點選，地圖從手機目前位置開始；拒絕定位則從目前畫面開始。使用者點的座標是自有資料，不使用任何地址轉座標服務。
- 地圖只標大概位置；精確位置與導航交給 Google 地圖。有連結時「在 Google 地圖開啟」直接開該連結；沒有連結時以座標組 Google 地圖搜尋網址，不用 API。
- 店家使用 App 自己的 ID。Google 分享短網址每次都不同，不能當 ID；後端展開短網址，存展開後的完整網址，並取出 Google 店家代碼（如 `0x…:0x…`），只作為新增時的查重提示。展開失敗時照存短網址，只少了代碼查重，不擋使用者。ponytail：此代碼依賴 Google 網址格式，格式改變時查重提示會失效，但不影響店家資料與導航。
- 私房小店（如夜市攤販）可能沒有 Google 地點，所以連結不必填。
- 連結只接受 `https://maps.app.goo.gl/`、`https://www.google.com/maps`、`https://maps.google.com` 開頭，其他提示「請貼 Google 地圖的分享連結」。
- 名稱相近：pg_trgm 相似度 ≥ 0.3，只比對大概位置 2 公里內的店家，最多列 5 家。ponytail：門檻憑經驗訂，試用時依誤報調整。
- 新店家一建立即進入共用店家庫，其他使用者可立即搜尋選取，不必等核對。
- 系統方核對見情境 06。「未核對」只在店家頁標示，地圖標記不區分。
- 依自己距離排序時，手機定位僅用於當下排序，不保存；拒絕定位則依店名排序。

## 02｜找回之前吃過的店

狀態：已定案（2026-10-23），亮度計分公式定案（2026-10-24）。

### 地圖

- 底圖：MapLibre＋自放 Protomaps 台灣圖資，黑色陸地、只畫主要道路與行政界線，見 [custom-map-prototype.md](../tech/custom-map-prototype.md)。
- 只顯示自己的私房店；回憶不顯示。
- 打開地圖時以手機目前位置為中心，拒絕定位則以高雄火車站為中心，兩者都用固定縮放比例（約可看到半徑 1 公里）；完全沒有私房店時另外提示「記下你的第一家店」。定位不保存。地圖只撈畫面附近的私房店，見 [api.md](../tech/api.md)。
- 篝火樣式依店家的亮度（共用店家資料，由所有使用者的到訪與回訪累積分數決定）分三級。使用者只會間接得知店家有其他人來過，不會看到是誰或內容。

### 亮度計分

- 分數 = 到訪過的不同使用者數 + 2 × 來訪天數 ≥ 2 的使用者數。自己也算在內，所以地圖上每家店至少 1 分。
- 1–2 分一級、3–5 分二級、6 分以上三級。ponytail：門檻依試用規模（幾位熟人）訂，正式開放時依實際分布調整。
- 不看評價（亮度代表熱度，不代表品質）；沒有時間窗與衰減，分數只因刪除而下降。原構想的「每月到訪人數超過門檻 +3」與熄滅的篝火留待之後。
- 回憶中的到訪照常計入；刪除到訪、永久刪除或刪除帳號時，依剩餘資料重算。

### 預覽卡與店家頁

- 點篝火先顯示預覽卡：店名、自己最近填的價位（從沒填過就不顯示這行）、「在 Google 地圖開啟」；點預覽卡進完整店家頁。
- 店家頁由上到下：店名與「未核對」標示、最新一次評價與來訪天數、補充資訊（每項顯示最近一次有填的值，否則「不清楚」）、「在 Google 地圖開啟」、「新增到訪」、到訪列表（新的在上，每筆有日期、評價、筆記與刪除按鈕）、最底部不顯眼的「成為回憶」。

### 我的私房店清單

- 個人選單有「我的私房店」清單，列出所有非回憶的私房店，依最近一次到訪排序，可依店名搜尋；回憶清單另外分開。

### 例外

- 同一店家同一天可記錄多筆到訪，不設限；來訪天數以不同日期計算，同一天多筆只算一次。
- 儲存失敗：保留已填內容，提示「儲存失敗，請再試一次」。
- 填寫到一半離開：不保留草稿。

## 03｜再次到訪

狀態：已定案（2026-10-24）。

- 入口：店家頁的「新增到訪」；或在新增店家的搜尋中選到自己有到訪的店（結果標「已記錄」），點擊開啟店家頁。預覽卡不放捷徑。
- 表單與情境 1 的到訪欄位相同，不預填任何值（含評價與補充資訊），未填仍代表「不清楚」。
- 儲存後回到店家頁，新到訪出現在列表最上方，短暫提示「已記下這次到訪」。當天已有到訪時來訪天數不變。
- 例外同情境 2：儲存失敗保留已填內容；不保留草稿。

## 04｜刪除到訪

狀態：已定案（2026-10-24）。

- 沒有修改功能；要更正只能刪除到訪後重寫。到訪日期固定為記錄當下，所以刪掉的過去到訪無法補回。
- 店家頁每筆到訪都有刪除按鈕，任何一天的到訪都能刪除。確認訊息：
  - 一般：「刪除這筆到訪？過去的到訪刪除後無法補回。」
  - 最後一筆：「這是此店最後一筆到訪，刪除後這家店會從你的地圖消失，無法補回。」
- 刪除後來訪天數、最新一次評價、補充資訊與預覽卡價位都從剩餘到訪重新推算，不另外存。
- 刪除最後一筆後回到地圖，篝火消失；共用店家資料保留。

## 05｜成為回憶、復活與永久刪除

狀態：已定案（2026-10-24）。

- 成為回憶：店家頁最底部不顯眼的按鈕，確認「這家店會從地圖消失、移到回憶，之後可以復活。」後回到地圖。不必新增到訪或評價，原有到訪全部保留。
- 回憶清單：在個人選單，依成為回憶的時間排序（新的在上），可依店名搜尋，每列顯示店名與來訪天數。
- 回憶的店家頁：不同色系、唯讀，不能新增或刪除到訪；只有「復活」與「永久刪除」。想刪單筆到訪需先復活。後端也擋：對回憶新增或刪除到訪回 409「此店在回憶中，請先復活」（別人的資料一律 404）。
- 新增店家的搜尋選到自己回憶中的店：結果標「在回憶中」，點擊開啟回憶的店家頁。不提供「復活並新增到訪」的合併動作。
- 復活：不需確認，店家回到地圖並置中；不產生到訪。
- 永久刪除：確認一次「永久刪除這家店的全部 N 筆到訪？無法復原。」，刪除所有到訪與回憶後回到回憶清單；共用店家資料保留。

## 06｜系統方核對店家

狀態：已定案（2026-10-24）。

- 目的：確認店名、大概位置與 Google 連結對得上同一間實際店家，並合併重複建立的店家。
- 核對一律建立一筆新的已核對店家，把舊店家底下的到訪全部改記到新店家，舊店家標「已被取代」並記下新店家。單一店家修正與多家合併都是同一個動作。
- 已被取代的店家不出現在搜尋；打開舊店家頁會導到新店家。保留使用者當初輸入的店名與位置。
- 到訪不合併、不刪除，只改記到新店家；來訪天數與亮度從到訪重新計算，重複的篝火自然消失。
- 回憶：同一人在被合併的店家中，只要有一家不是回憶，新店家就不是回憶；全部都是回憶時保留一筆，時間取最晚的。
- MVP 不做管理介面。系統方透過管理 API 操作（預計交給 AI），API 以環境變數中的管理 token 驗證（`Authorization: Bearer`），不檢查 `Origin`。ponytail：單一共用 token，外流就得換；與邀請碼同等級。
- 管理 API 只有兩支：列出未核對店家（只回傳店家 ID、店名、大概位置、Google 連結與代碼、建立時間，不含任何使用者資料）；核對（傳入一或多個舊店家 ID 與新店家資料，整個在同一個交易內完成）。使用說明在設計階段寫成 `DOC/admin-api.md`。
- 店家搬家、歇業等之後再說。
